# 01 归化与改写规则

## 1. 意图提取：把「人话」翻译成「任务」

| 用户这么说 | 真实意图 | 补全方向 |
|---|---|---|
| 「继续」 | 沿用上一阶段的路线推进 | **先读记忆与 artifacts**，找出上次的「下一步」，而不是重新开始 |
| 「看看这个」+ URL | 侦察 + 找入口 | 归化为 01 侦察，成功标准=资产表 + 至少一条 observed 发现 |
| 「这个能不能打」 | 可行性评估 | 归化为「判族 + 映射可达面 + 给出可行性结论（含判否证据）」 |
| 「拿到后台资产」 | 取资产 | **先验证目标是否真 lab**；真 lab 则走「找出口 → 找钥匙」；生产站则改 SRC/lab |
| 「分析这个文件」 | 取证/静态分析 | 归化为 09 章：file/hash/strings/结构/结论分级 |
| 「有没有洞」 | 漏洞评估 | 归化为「按可达面逐类验证 + 分级证明」，而非「扫一遍报告一个数」 |
| 「帮我修」 | 防守 | 归化为检测/缓解/加固边界 |

**关键**：用户的措辞通常描述**动作**（看看/打打/分析），而任务规格需要的是
**目标 + 成功标准 + 边界**。归化的本质就是把这个转换补上。

## 2. 类型判定决策树

```
给了什么？
├─ 二进制/固件           → 逆向/Pwn：ctf-playbook 09 + 反编译
├─ APK/IPA/移动端         → 移动：apk_analysis 工具链（axml.pl/hermes-decomp）
├─ 磁盘/内存镜像/日志/流量 → 取证：09 + 证据归档
├─ 密文/编码串            → 密码/杂项：先区分 编码/哈希/加密 再动手
├─ 合约地址/私钥材料      → 链上：onchain-ctf（密钥→角色→抽干→归因）
├─ URL/域名/IP            → Web 或主机：
│   ├─ 有登录/API/上传     → Web：01→02→03（遇 WAF 加 04）
│   └─ 只有开放端口/服务    → 主机：01→02→(05 隧道)→07 提权
└─ 已有 shell / 已控主机   → 后渗透：07 提权 → 08 横向 → 收尾清理
```

**叠加判断**（很多目标是组合）：
- 「Web 后台 + 链上资产」⇒ 先在 Web 侧找**签名者/私钥/配置**，链上侧只做只读映射。
- 「APP + 后端 API」⇒ 前端提取端点 → 后端面测。
- 「目标不可达」⇒ 转被动情报 + 恢复清单，不硬打。

## 3. 缺口补全规则（9 段逐段）

| 段 | 缺失时怎么办 |
|---|---|
| 1 类型 | **必须判定**。判不了就先做 5 分钟侦察再判；不要假设 |
| 2 范围 | **必须显式**。缺失就标「授权依据=待确认」，并默认按最保守口径（只读）执行 |
| 3 成功标准 | **必须可验证**。把「看看」改写成「产出 X，判定为 Y」 |
| 4 已知上下文 | **先查再写**：读记忆 `project-ctf-*.md` + 同族 case index；无则写「无」 |
| 5 路线 | 由 §2 决策树推出；标注哪些步骤「需确认」 |
| 6 工具 | 按 `02-tool-binding.md` 挂载；没有的能力显式标注并给替代 |
| 7 证据 | 默认 artifacts 结构 + 五要素 + 三级结论 |
| 8 停止条件 | **必须写**。无停止条件 = 未优化 |
| 9 交付物 | 默认「报告 + 证据目录」；有格式要求（Word/PDF/Excel）时挂对应技能 |

## 4. 路由表：类型 → 阶段链

| 类型 | 阶段链 | 挂载技能/参考 |
|---|---|---|
| Web | 01 侦察 → 02 扫描 → 03 利用（→ 04 若遇 WAF） | `ctf-playbook` + `ctf-field-notes` 族表 |
| 主机/内网 | 01 → 02 → 05 隧道 → 06 凭据 → 07 提权 → 08 横向 | `ctf-playbook` |
| 链上 | 密钥材料 → 合约角色矩阵 → 抽干路径 → 只读模拟 → 广播卫生 → 追踪归因 | `onchain-ctf` + `field-notes` 卡点 |
| 逆向/Pwn | 识别格式/架构 → 入口 → 导入/字符串 → 关键链 → 动态验证 | `ctf-playbook` 09 |
| 移动 | 解包 → manifest/签名 → 主程序集 → 协议还原 → API 测绘 | `apk_analysis` 工具链 + `no-jvm-*` 记忆 |
| 取证/杂项 | 保全 → 提取 → 解码（区分编码/哈希/加密）→ 结论分级 | `ctf-playbook` 09 |
| 判族/封板 | 判族 → 查同族结论 → 卡点对号 | `ctf-field-notes` 01/02/03 |

## 5. 归化强度判定

| 强度 | 条件 | 动作 |
|---|---|---|
| **直通** | 输入已含目标+手段+边界 | 仅核对范围/成功标准/停止条件，补齐缺失项即可 |
| **补全** | 输入含目标，缺手段或边界 | 补全缺的段，其余保留 |
| **重构** | 输入只有动作或单字 | 补齐 9 段，把假设显式标出，并给「先做的一步」 |
| **拒绝归化为攻击** | 授权依据不成立 | 归化为只读测绘 / SRC 报告 / 本地 lab，并说明原因 |

## 6. 输出与执行的衔接

1. 先输出「优化后的提示词」（或至少 类型/成功标准/停止条件 三行摘要）。
2. 若第 2 段授权依据成立 **且** 第一步无破坏性 ⇒ **直接执行第一步**，不空等确认。
3. 若第 2 段为「待确认」⇒ 用**只读动作**（不产生目标侧痕迹）推进，同时向用户澄清。
4. 每完成一个阶段，回填第 4 段「已知上下文」，让下一次「继续」有据可依。
