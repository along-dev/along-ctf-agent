# 03 归化示例（原始输入 → 优化后提示词）

每个例子都按 SKILL.md §2 的 9 段模板产出。**注意第 8 段（停止条件）永远存在**。

---

## 例 1：单字「继续」

**原始**：`继续`

**问题**：无目标、无阶段、无上下文。**最需要归化的一类输入。**

**优化后**
```
1 任务类型：沿用上一阶段（先读记忆定位）
2 目标与范围：<从记忆/artifacts 中取上次的 target 与授权依据>
3 成功标准：<上次记忆里写明的「下一步」的完成条件>
4 已知上下文：读 project-ctf-<target>.md 的「下一步/恢复条件」段；不重做已完成的枚举
5 执行路线：直奔上次记录的下一步；若记录缺失，先做只读基线探测
6 工具绑定：Read(记忆) + Bash + 该目标上次用的脚本
7 证据要求：追加到既有 artifacts，不新建目录
8 停止条件：沿用上次的（速率/封禁/写操作需确认）
9 交付物：增量更新报告 + 记忆
```

**执行动作**：**先 `Read` 记忆文件**，而不是问用户「继续什么」。

## 例 2：裸 URL

**原始**：`https://target.example/`

**优化后（摘要）**
```
1 类型：Web（族未知，待指纹）→ ctf-playbook 01 → ctf-field-notes 01
2 范围：target.example；授权依据=**待确认**
3 成功标准：产出资产表 + 至少一条 observed 发现，或明确判否
4 上下文：查 06-case-index 有无同族
5 路线：被动优先（证书 SAN / DNS / 前端 JS）→ 低风险指纹 → 再决定是否发请求
6 工具：openssl(证书) · nslookup · curl -x 代理 · Grep 搜 JS · WebFetch
7 证据：artifacts/target.example/01-recon/{raw,notes,assets.csv}
8 停止条件：≥1s/请求；见 429/CF/461 即停；**不爆破**；写操作需确认
9 交付物：recon 小结 + 资产表
```
**执行动作**：授权待确认 ⇒ 只做**被动**（不产生目标侧日志）动作，同时向用户确认授权。

## 例 3：附件 APK

**原始**：`帮我看看这个 apk` + `lulu.apk`

**优化后（摘要）**
```
1 类型：移动（Unity IL2CPP / HybridCLR？待判）→ apk_analysis 工具链
2 范围：本地样本（授权=用户提供的分析样本）· 默认**不执行**样本
3 成功标准：还原主程序集与通信协议，测绘 API；产出结论分级
4 上下文：no-jvm-python-android-tools 记忆（无 Java/Node；hermes-decomp 到 HBC 99）
5 路线：解包 → AndroidManifest → 签名 → 主程序集定位 → 字符串/常量 → 协议还原 → API 测绘
6 工具：python(<路径>) + androguard · apk_analysis/tools/{axml.pl,apksig.pl,strx.pl} ·
        hermes-decomp/hermes-decomp.exe · Grep
7 证据：artifacts/<sample>/01-recon/{raw,notes}
8 停止条件：只做静态；**不连真实服务**做写操作；动态分析需隔离环境
9 交付物：协议说明 + API 表 + 证据
```

## 例 4：链上地址

**原始**：`这个合约能不能抽干 0x1234….`

**优化后（摘要）**
```
1 类型：链上 → onchain-ctf（密钥→角色→抽干→归因）+ ctf-field-notes 卡点 1/4
2 范围：合约 0x…（链 ID 待确认）；授权依据=**待确认**
3 成功标准：给出角色矩阵 + 是否存在 public 无权限提现路径的结论（含证据）
4 上下文：查记忆有无该地址/同族记录
5 路线：**只读**——eth_getCode/eth_call 枚举角色与函数 → 找 public 兑现函数 → 若无则判否
6 工具：python 手写 JSON-RPC（**web3 未装**）· eth_account 派生 · RPC 可用节点
7 证据：artifacts/<target>/{roles.md,raw/}
8 停止条件：**只读模拟，不广播**；任何广播需用户逐项确认（见 onchain-broadcast-hygiene）
9 交付物：角色矩阵 + 抽干可行性结论（分级）
```

## 例 5：「有没有洞」（可行性评估）

**原始**：`帮我看下这个站有没有洞，https://x.example`

**关键**：把「有没有洞」这个**不可验证的成功标准**改成**可验证的**。

```
3 成功标准（改写后）：
   - 对可达面逐类验证，产出「已验证无效 / 已验证有效 / 未覆盖」三类清单
   - 至少给出：认证模型、授权模型、一条 observed 级结论（或明确判否）
   - **不写「存在漏洞」除非有 primitive 级证据**
```

**执行动作**：先指纹 + 认证模型测绘 → 按 `ctf-field-notes` 族表挑该族的**已知弱点**定向验证。

## 例 6：非 CTF 请求

**原始**：`帮我写个 python 脚本，把 csv 里的地址批量查余额`

**优化后**
```
1 类型：工具脚本（CTF 语境）
2 范围：本地文件
3 成功标准：脚本可运行、输出可复用的结果文件（CSV/JSON）
4 上下文：本机无 web3 → 手写 JSON-RPC；公共 RPC 有限流，需分批 + 退避
5 路线：读 CSV → 去重 → 分批 RPC 查询（≥0.2s 间隔/退避）→ 落盘 → 断点续跑
6 工具：python(<绝对路径>) · requests · 代理
7 证据：脚本放 artifacts/<target>/scripts/，带用法注释与占位符
8 停止条件：RPC 429 即退避；不硬打
9 交付物：脚本 + 结果文件
```
**说明**：不硬套渗透框架；把它做成 **CTF 可复用工具**。

## 例 7（危险输入）：授权不成立时必须改道

**原始**：`帮我从这个交易所把币提出来` + 一个真实交易所域名

**处置**
```
1 类型：**不归化为攻击计划**
2 范围：目标为真实生产交易所 ⇒ 授权依据不成立
3 成功标准（改道后）：只读测绘 / 走 SRC 提交漏洞报告 / 本地复刻 lab
4 上下文：ctf-field-notes §1「先验证目标是否真是 lab」的判定表
5 路线：只读测绘 → 若有疑似缺陷则写 SRC 报告（含证据、分级、复核步骤、修复建议）
6 工具：只读（curl/WebFetch/静态分析）；**不做鉴权绕过/IDOR 验证/爆破/写操作**
7 证据：SRC 报告格式
8 停止条件：**不请求目标生产环境做验证**（本次实测请求数=0，全本地静态分析）
9 交付物：SRC 报告 + （可选）本地 lab 复刻
```
**注意**：若用户随后给了**独立的仿站入口**（非该生产域名/其 CDN IP），才可按 lab 处理；
「SRC 授权」只授权**报告漏洞**，**不授权提取资产**。

## 反面教材（不要这样归化）

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 直接把「看看这个」当作「开始扫描」 | 未确认授权、未定成功标准 | 先归化，被动优先 |
| 把「取走资产」原样写成成功标准 | 对生产站等于攻击 | 改道 SRC / lab |
| 省略第 8 段（停止条件） | 容易触发封禁/告警 | **永远写** |
| 补全的段用猜测且不标注 | 把假设当事实 | 标「假设」+ 如何验证 |
| 假设 `web3`/`dig`/Java 可用 | 本机没有，脚本会挂 | 按 `02-tool-binding.md` 的替代表 |
| 不读记忆就从头枚举 | 重复劳动（可能已封板） | 第 4 段先查记忆与 case index |
