# PLAYBOOK.md — 作战手册

把 Kill Chain 各阶段串成可复用的**剧本**。每个剧本给出：适用场景 → 阶段编排 → 决策点 → 产出。执行时对照本手册逐步推进，每阶段产出落盘再进下一阶段。

## 通用原则

- **先侦察后打击**：没摸清攻击面不动手，避免盲打留痕。
- **最小化验证**：漏洞先做最小 PoC 确认可利用性，再决定是否升级利用。
- **每步落盘**：命令、输出、证据全部进 `runs/<run_id>/`，方便回溯与出报告。
- **并行优先**：侦察/测绘/扫描对多目标并行；单目标内部串行。
- **失败可回退**：一步失败先换路径，不硬顶。

## 剧本 A：外部 Web 打点（最常见）

**场景**：给定一个域名，目标是拿到 Web 应用立足点。

| 阶段 | 动作 | 工具 / 接口 | 判据 |
|---|---|---|---|
| 1 侦察 | 子域枚举 + 存活指纹 | `recon.run_recon(domain)` | 拿到存活 Web 资产清单 |
| 2 测绘 | 目录爆破 + 参数发现 | `scanner.fuzz_dirs` / ffuf | 找到登录框、上传点、API、隐藏参数 |
| 3 验证 | 模板扫描 + 手动验证 | `scanner.scan_vulns` + 手动 | 确认至少一个高危 |
| 4 打点 | 利用链串联 | sqlmap / 手写 POC | 拿到命令执行或文件读写 |
| 5 报告 | 汇总 | `report.render_report` | 出 MD 报告 |

**决策点**：
- 子域很多 → 先按状态码/标题筛，优先打后台、管理面板、测试环境。
- 目录扫描命中 `/backup`、`/.git`、`/swagger` → 转信息泄露路径，别急着打注入。
- 注入点存在但报错关闭 → 用时间盲注（sqlmap `--technique=T`）。

## 剧本 B：内网 / 域渗透

**场景**：已有一个内网会话，目标是横向到核心资产 / 域控。

| 阶段 | 动作 | 工具 | 判据 |
|---|---|---|---|
| 1 环境判断 | 出网、权限、域信息 | `id;whoami;hostname;ipconfig` | 摸清自己在哪 |
| 2 内网探测 | 存活主机 + 端口 | nmap `-sn` / masscan | 内网拓扑 |
| 3 凭证获取 | 抓哈希 / 找明文 | impacket-secretsdump、mimikatz 类 | 拿到可复用凭证 |
| 4 横向 | psexec/wmiexec | impacket 套件 | 控制新主机 |
| 5 提权 | 本地提权 | linpeas / winpeas | 高权限会话 |
| 6 目标 | 域控 / 核心 | DCSync 等 | 达成目标 |
| 7 报告 | 攻击路径图 | `report` | 出报告 |

**决策点**：
- 有域管哈希 → 优先 DCSync，别横向多台暴露。
- Kerberoast 出 SPN 账号 → 离线破解（hashcat `-m 13100`）。
- 找不到出网 → 建隧道或走已有 C2 通道。

## 剧本 C：CTF 速通

**场景**：CTF 单题，按类型分流。

| 类型 | 思路 | 工具 |
|---|---|---|
| Web | 看源码/参数/源码泄露 → 逐个漏洞面 | ffuf / 手测 |
| Pwn | 查保护 → 找漏洞点 → 写 exp | gdb / pwntools |
| Crypto | 识别算法 → 找弱点（低指数、复用 nonce、RSA 共模） | 自写脚本 |
| Re | 静态反编译 → 找校验逻辑 → patch/keygen | ghidra / frida |
| Misc | 看文件头 → 隐写 → 流量/编码分析 | binwalk / 手工 |

**决策点**：
- Re 遇到壳 → 先脱壳（frida dump 或手工）再分析。
- Crypto 给大数 → 先分解（factordb / yafu）。
- Misc 卡住 → 换编码思路（base、异或、rot、图片最低位）。

## 剧本 D：逆向专项

**场景**：无源码二进制，要搞懂逻辑或绕过。

1. **识别**：`file`、查壳（PEiD/die），判断语言（Go/Rust/C++）。
2. **脱壳**：有壳先脱（frida dump / 手工）。
3. **静态**：ghidra 反编译，定位关键函数（字符串、导入表、交叉引用）。
4. **动态**：frida hook 关键函数，看运行时值。
5. **利用/绕过**：patch 跳转、keygen 还原算法、绕过校验。

**决策点**：
- 算法看不清 → 动态跟，下断点看输入输出的关系。
- 反调试干扰 → 先 patch 掉反调试，再分析。

## 多 AI 协作（六角色分派）

复杂任务拆六个角色并行，每个子 agent 独立上下文，结果汇总回主流程：

| 角色 | 职责 | 产出 |
|---|---|---|
| 侦察 | 资产、端口、指纹 | 攻击面清单 |
| 审计 | 代码/配置/漏洞面分析 | 候选漏洞点 |
| 利用 | POC 编写与验证 | 可利用漏洞 |
| 免杀 | 载荷对抗处理 | 可用载荷 |
| 内网 | 横向、提权、凭证 | 控制面扩大 |
| 报告 | 汇总与出稿 | 最终报告 |

分派方式：Agent 工具（`subagent_type=general-purpose`），一次性并行下发给多个角色。
