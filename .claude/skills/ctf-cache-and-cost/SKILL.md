# 缓存与成本 · ctf-cache-and-cost

> 定位：这是**效率层**。CTF 侦察很贵（token、时间、对目标侧的请求数），本技能管
> "什么该缓存、什么该重跑、拆不拆子 Agent"。

## 0. 三类缓存

| 缓存 | 放哪 | 有效期 | 命中判据 |
|---|---|---|---|
| 侦察结果（子域/指纹/目录） | `artifacts/<target>/` | 会话内 | 目标+时间窗一致 |
| 已判否结论 | `ctf-field-notes/references/04-case-index.md` | 跨会话 | 同族+同卡点 |
| 合约字节码/ABI | `artifacts/<target>/chain/` | 会话内 | 地址+区块号一致 |

## 1. 重做前先问三句

1. 这次输入的 target 和上次一样吗？（不一样 → 不读缓存，但可参考同族结论）
2. 上次结论还新鲜吗？（时间窗内 → 读；过期 → 重跑但 diff 增量）
3. 重跑的信息增益 > 成本吗？（只差一个字段 → 只补那个字段，不全量重跑）

## 2. 拆子 Agent 的判据

| 场景 | 拆不拆 | 理由 |
|---|---|---|
| 多个独立目标并行侦察 | 拆（并行） | 独立无依赖，并行省墙钟时间 |
| 需要翻大量文件/网页 | 拆 | 子 Agent 独立上下文，不占主对话 |
| 有依赖的串行攻击链 | 不拆 | 上下文需要连续，拆了丢线索 |
| 单目标单线 | 不拆 | 拆的调度成本 > 收益 |

## 3. 成本对比口径

- **重跑成本**：目标侧请求数 + token + 墙钟时间。
- **读缓存成本**：一次文件读 + 命中校验。
- 报"命中率"时口径统一：`命中次数 / (命中 + 未命中)`，且注明统计窗口。

## 4. 最小示例

**输入**：昨天扫过这个站，今天还要再扫一遍吗

```
1 查缓存：artifacts/<target>/ 有无昨日侦察结果
2 判新鲜：目标侧是否可能变更（改版/上线新服务）→ 增量 diff
3 结论：只重跑"可能变化"的资产（存活/指纹），不重跑全量子域枚举
4 命中率：本次 70% 命中缓存，仅 30% 重跑
```
