# 02 卡点症状 → 解法

连续 2-3 次验证无进展时，按症状对号，别闷头重试。

## 卡点表

| 症状 | 可能原因 | 解法 |
|---|---|---|
| 全部 404 / 长度一致 | 统一 404 页 / 路由框架 | 建 404 baseline，看响应差异，改扫路径/参数 |
| 403 | 访问控制 / WAF | 记线索不结论；换 UA/Header、看允许方法、找旁站 |
| 429 / 1015 / 461 / 封 IP | 触发限流或 WAF 封禁 | 立即停，降速，转被动，或封板 |
| 有回显但无数据 | 查询被过滤/参数错 | 改编码/大小写/注释绕过，逐字符探测 |
| 能读不能写 | 权限边界 | 读取与写入是两条链，先确认写入点 |
| 能写不能执行 | 缺执行原语 | 回到上传/包含/反序列化/命令注入找执行点 |
| 本地复现远端无效 | 环境差异 | local_proof ≠ remote_proof，别外推结论 |
| 反连不回显 | 出网受限/DNS 被拦 | 用 DNSlog 验证出网，换 ICMP/DNS 通道 |
| 爆破全锁 | 账号锁定策略 | 停爆破，改撞库/凭证复用，先查默认凭据 |

## 通用原则

1. **换维度前先记录**：每次卡住写一条"试了什么 → 观察 → 结论"，避免循环重试。
2. **回退到更上层**：注入无果 → 回到认证模型；执行无果 → 回到信息收集补攻击面。
3. **卡点即证据**：`blocked` 状态 + 原因也是结论的一部分，写进 case index。
