# 03 封板判据与动作

封板 = 判定当前方向已死并记录，不是放弃任务，是切换路线或收敛结论。

## 封板判据（满足任一即封板）

1. **覆盖判否**：该族全部已知弱点已逐类验证，全部 negated。
2. **触发停止条件**：429/1015/461/锁定/告警，且无法换源（换 IP/换工具/换时间窗）继续。
3. **证明到顶**：结论已足够支撑"判否"或"已到证明上限"，继续加成本无信息增益。
4. **范围外**：目标明确在授权范围外 → 转只读/封板 + 记录，不扩大。

## 封板动作（三件必做）

1. 写 case index 一条（`references/04-case-index.md`）：`case_id, family, target, why_closed, evidence, what_to_try_next`。
2. 产出封板小结：已覆盖哪些面、判否哪些、留了哪些未覆盖（诚实标注）。
3. 明确"下次可试"：换路线 / 换工具 / 换时间窗 / 转人工。

## 反模式（禁止）

- 把 `blocked` 写成"漏洞不存在"。
- 用"没扫到"代替"判否"（要逐类验证 + 证据）。
- 无限降速重试同一动作（换维度，不换姿势）。
