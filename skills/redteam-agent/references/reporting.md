# 渗透报告模板

报告落盘为 MD（如 `report_<target>_<date>.md`），需要 PDF 时再转换（pandoc / wkhtmltopdf / 浏览器打印）。结构如下，按需裁剪。

---

## 封面

- 项目名称
- 目标范围（域名 / IP 段 / 系统）
- 测试时间窗
- 报告版本与密级
- 测试方 / 授权依据

## 1. 执行摘要

- 本次测试总体结论（一句话定性）
- 高危 / 中危 / 低危 / 信息 漏洞数量统计（表格）
- 最关键的风险点（Top 3）

| 严重级别 | 数量 |
|---|---|
| 严重 Critical | [n] |
| 高危 High | [n] |
| 中危 Medium | [n] |
| 低危 Low | [n] |

## 2. 攻击路径图

用文字链或 ASCII 图描述从入口到目标的完整利用链：

```
外网暴露点 → 漏洞A(类型) → 立足点 → 内网横向 → 提权 → 凭证复用 → 域控/核心资产
```

## 3. 漏洞详情

每个漏洞一节，字段固定：

- **漏洞名称**
- **风险等级**（CVSS 3.1 评分）
- **影响资产**（URL / IP:Port）
- **漏洞描述**（成因 + 影响）
- **复现步骤**（编号步骤，含请求/响应关键片段）
- **证据**（截图占位 `[screenshot_xxx.png]`）
- **修复建议**（具体可落地）

## 4. 攻击面清单

端口 / 服务 / 版本 / 指纹表，隐藏资产与暴露面一览。

## 5. 权限与凭证成果

获取的会话、账号、哈希等（脱敏，用于验证控制面）。

## 6. 风险总结与修复优先级

按「影响 × 利用难度」排序的修复清单。

## 7. 附录

- 工具与版本
- 测试命令记录
- 术语表

---

## 写作原则

- 每个结论都要有证据支撑，不写无据推断。
- 复现步骤要让第三方能照着走通。
- 明确区分「已验证事实 / 推断 / 待确认」。
- 报告本身就是交付物，落盘后给出路径。
