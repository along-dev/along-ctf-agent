# 05 内网隧道 & 代理穿透

**目标**：内网服务不直接暴露时，在两段网络间搭转发通道。

## 概念别混淆

| 概念 | 大白话 |
|---|---|
| 正向代理 | 你让代理帮你访问外部 |
| 反向代理 | 外部访问代理，代理转后端 |
| 端口转发 | 一个端口流量转到另一个地址端口 |
| SOCKS 代理 | 通用代理协议，转多种 TCP |
| HTTP 隧道 | 把其他协议包进 HTTP 传 |
| 反向隧道 | 内网端主动向外连，外部通过该连接访问内网 |

## 检查清单

1. **选隧道类型**：
   - 反向穿透（内网机器主动连外网）→ frp（TCP/UDP/HTTP/HTTPS）
   - WebShell 隧道（已有 Web 入口）→ Neo-reGeorg、suo5（WebSocket）
   - 全局代理（本机应用统一走代理）→ Clash、Proxifier
2. **记录拓扑**：`本机 → 本地代理 PORT → 中转 HOST:PORT → 靶场 TARGET:PORT`，画图存 topology.md。
3. **配置认证**：token/TLS/来源限制，别让中转端口被别人滥用。
4. **DNS 走代理**：避免泄露真实查询或访问失败。
5. **收尾**：关代理、删临时账号、撤销端口暴露，写 cleanup.md。

## 工具（可核验来源）
frp、Neo-reGeorg、suo5、Clash（原仓库已归档，注意分支来源）、Proxifier。

## 证据模板
```text
server / client / local_port / remote_port / protocol / auth / logs
```

## 防守视角
内网主机异常长连未知 VPS、非运维机器跑 frpc、出站端口协议异常、同一 Web 入口访问多个内网 IP:PORT、高熵且大小接近的请求体——都是隧道特征。检测「代理/隧道行为」，不是检测工具名（工具可改名）。

## 常见误区
能通就行（不留日志规则）｜全局代理开太宽｜只检测工具名｜忽视 DNS｜隧道不做认证。
