# 11 路径穿越 & 文件上传（含 Vue 头像上传典型场景）

**目标**：证明「后端把用户输入拼进文件路径」这一原语，并**分级**验证它到底能读到什么、写到哪。不做「传个马就等于拿 shell」的跳级结论。

## 原理（一句话）

后端把用户可控的路径片段（`file.name`、URL 参数、`filename` 字段）**直接拼接**到真实文件路径上，且未过滤 `../`，于是你可以跳出预期目录，读到/写到本不该碰的位置。

```js
// 典型脆弱写法（观察到的模式，非源码原文）
const p = "/uploads/avatar/" + file.name;   // file.name 用户可控
fs.writeFileSync(p, file.buffer);            // 未做 basename / 规范化
```

## 两种形态

| 形态 | 入口示例 | 危害方向 | 证明要点 |
|---|---|---|---|
| **读**（路径穿越读取） | `/download?file=../../../../etc/passwd` | 信息泄露 | 读到**已知内容**的文件才算证明 |
| **写**（上传路径穿越） | `filename=../../public/index.html` | 覆盖/写马（更危险） | 先写**无害标记文件**验证落点，再谈利用 |

## 检查清单（按序执行）

1. **抓包定位入口**：Burp/Fiddler 抓上传与下载请求，标记可控字段：`filename`、`name`、`path`、`file` 参数、`Content-Disposition`、multipart 各段。
2. **先测「能不能逃逸」，不测「能不能拿 shell」**：读场景先读 `../../../../etc/passwd`（Linux，内容是已知的）或 `..\..\..\windows\win.ini`（Windows）；写场景先写一个**无害标记文件**（如 `PWNED_TEST.txt`），再去预期/上级路径搜索它是否存在。
3. **确认落点**：通过回显、返回的存储路径、或直接访问 `/uploads/xxx`、`/uploads/../xxx` 判断文件最终落在哪一层。**只在授权目录内验证。**
4. **判断过滤强度**：单测 `../`、多重 `....//`、URL 编码 `..%2f`、二次编码 `..%252f`、绝对路径、后缀约束。
5. **分级证明**：逃逸成功(可读到已知文件/标记文件出现在非预期位置) → 读取敏感文件(有内容) → 写入可控内容(有回读) → 覆盖可达点/执行(最高，须授权+隔离+回滚)。
6. **收尾**：删除所有测试标记文件与上传物，还原被覆盖文件，记录 cleanup。

## Vue 前端场景特征

Vue/SPA 后台的「通用头像上传」「附件上传」接口，后端常为文件路径直拼；前端打包后源码不可读，**看后端行为而非读前端源码**。常见部署路径线索（用于推断跳几层，需实测确认，别当定论）：

- 项目根常在 `/var/www/html/dist/` 或 `/var/www/html/`
- 资源常在 `/uploads/avatar/`、`/public/`、`/static/`
- 头像目录里跳 3–4 层可能回到站点根 → 试探 `../../../dist/index.html`、`../../dist/index.html`

> 观察到的结构只是**试探起点**；真实落点用标记文件确认，不要假设。

## 常见绕过姿势（按过滤类型选）

| 过滤了什么 | 尝试 |
|---|---|
| 只删一次 `../` | `....//....//`（删完仍剩 `../`）、`..././`、`....\/` |
| 做了 URL 编码 | `..%2f`、`..%c0%af`（旧解析器）、`..%252f`（二次编码） |
| 强制后缀 `.jpg` | 老版本 PHP `%00` 截断：`../../x.php%00.jpg`（PHP < 5.3.4，需实测） |
| 过滤了 `../` 但放行分号参数 | `..;/`（**Tomcat/Java 的路径参数 `;` 绕过**，非「Windows 特性」；是否生效取决于容器与版本，需实测） |
| 只校验 basename | 双写文件名 / 绝对路径 `/etc/passwd`（后端若直接拼接则生效） |

**用词提醒**：`..;/` 的成因是 Servlet 路径参数解析，不要写成「Windows 特性」；`%00` 截断只在特定旧运行时有效，结论前必须有实测证据。

## 关键命令速查（占位目标，低风险优先）

```bash
# 读穿越：读已知内容文件才算证明
curl -s "https://HOST/download?file=../../../../etc/passwd" | head
curl -s "https://HOST/download?file=....//....//....//etc/passwd" | head

# 写穿越：先写无害标记，再回读验证落点
# 通过 Burp 改 multipart 的 filename 字段：
#   filename="../../../public/PWNED_TEST.txt"   内容=PWNED-<随机标记>
curl -s "https://HOST/uploads/PWNED_TEST.txt"        # 回读，确认落点
curl -s "https://HOST/uploads/../PWNED_TEST.txt"      # 换个角度确认

# 编码/绕过变体（逐个单测，一次只改一个变量）
#   ..%2f  |  ..%252f  |  ....//  |  ..;/  |  绝对路径
```

## 证据模板（proof-chain.md）

```markdown
## REQUEST-ID
- 目标：https://HOST/PATH
- 入口：multipart filename / URL 参数 PARAM
- 原始请求/响应：raw/req-001.txt, raw/resp-001.txt
- 改动点：filename 从 "avatar.png" 改为 "../../../public/PWNED_TEST.txt"
- 观察结果：响应 STATUS / 回读 GET /uploads/../PWNED_TEST.txt → 200 且内容匹配
- 结论：observed（写穿越逃逸成功，落点 <路径>）/ negated
## 清理：已删除 PWNED_TEST.txt（时间 STAMP）
```

## 证明等级（沿用 03 的分级，禁止跳级）

```
路径可控 → 读到已知文件 → 读到敏感文件 → 写入无害标记 → 写入可控内容 → 覆盖可达点/执行
```

`上传成功` ≠ `写穿越成功` ≠ `RCE`。写入文件到**非预期位置有回读**才能说「写穿越成立」；能执行才算更高一级，且必须是授权+隔离环境。

## 防守视角

- Web access log：`../`、`%2f`、`%252f`、双重 `....//` 等异常路径在 URL 与 multipart filename 里是强特征。
- 文件系统：`/uploads/` 下出现非图片后缀、可执行内容、异常时间戳的新文件。
- 上传接口异常写入到 Web 根、模板目录、配置目录，会触发文件完整性/EDR 告警。
- 读取 `/etc/passwd`、`web.config`、`.env` 等**已知敏感路径**是 WAF/IDS 的固定检测项。

## 常见误区

传个马就等于拿 shell｜只测一类绕过就下结论｜不确认落点就说「写成功」｜把 `..;/` 说成 Windows 特性｜忽略 `%00` 的版本前提｜覆盖真实文件（危险，应先用标记文件）｜不清理测试文件｜用返回 200 当「文件存在」（很多站统一 200）。
