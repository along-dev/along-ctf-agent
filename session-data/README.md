# session-data — 会话记忆与工作临时数据

> **本目录用途（Owner 规定，2026-10-08）**：
> 所有对话 / 工作区的**会话记忆**与**工作临时产物**，一律放在本目录下，
> **不要散落在项目根目录，也不要与当前工作区同级。**
>
> 本目录是**可移植**的：整个工作区复制到任何目录 / 盘符 / 机器后，
> 相对结构不变，无需修改任何路径。

## 结构（相对工作区根）

```
<工作区根>/
└── session-data/
    ├── temp/          # 工作临时产物（工具运行输出、扫描结果、报告草稿等）
    │   └── runs/      # 编排脚本的默认输出根目录
    └── memory/        # 会话记忆的同步副本（可移植）
```

## 规则

1. **工作临时产物** → `session-data/temp/`
   - 编排脚本输出：默认 `session-data/temp/runs/<时间戳>/`
   - 报告草稿、扫描中间结果、下载的临时文件：`session-data/temp/`
   - 不往工作区根目录丢临时文件。

2. **会话记忆** → 归口管理（见下）
   - Claude Code 的 auto-memory 由 harness 按**工作区标识**自动落位，
     位置形如 `~/.claude/projects/<工作区标识>/memory/`（此路径由系统决定，不可改）。
   - 本目录下的 `session-data/memory/` 作为**可移植的记忆同步副本**，
     需要把记忆随工作区打包带走时，从系统记忆目录同步到此。

3. **命名约定**
   - 临时产物按 `<阶段>_<目标>_<时间>` 命名，避免覆盖。
   - 一次性调试文件用完即删，不长期堆积。

## 为什么不与工作区同级

- 工作区是要**打包复制分发**的（见 `PORTABLE.md`）。
- 会话记忆 + 临时产物是**本机运行态数据**，不该混进分发内容。
- 放 `session-data/` 独立子目录，便于：① 打包时排除 ② 清理时不误删源码 ③ 追溯会话产出。

## 打包 / 复制提示

复制工作区分发时，**排除或清空 `session-data/temp/`**（相对路径，任意盘符通用）：

```bash
# 在「工作区根」的上一级执行；<源>、<目标> 用相对或当前目录即可
# 例：复制当前目录到 newdir，排除临时数据与缓存
robocopy "." "newdir" /E /XD "session-data\temp" __pycache__ old_bak .git
```

> 记忆同步（从系统记忆目录 → 本目录，按需执行）：
> 把 `~/.claude/projects/<工作区标识>/memory/*.md` 复制到 `session-data/memory/`。
